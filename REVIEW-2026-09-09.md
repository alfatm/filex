## 1. Summary: what to fix first

Security and data loss (Wave 0):

1. **ZIP export hands out the service directories** `.filex-trash`, `.versions`, `.thumbs` to any account, including the viewer role —
   `GET /api/files/download/zip?path=main://` = every deleted file of every user and the entire version history (03-1).
2. **The activity feed hands out the share token** (including the anonymous-upload drop token) to anyone ≥viewer on the file (03-2).
3. **An assistant plan can execute twice**: `runPlan` runs before the `pending` claim; two approvals = two public links /
   restore on top of restore; a client disconnect leaves a half-done plan `pending` (02-1). The client does not guard against a double click (07-1).
4. **The `list_trash` / `plan_empty_trash` tools see the trash of the whole installation** without ACL (02-2), contrary to `docs/ASSISTANT.md:75`.
5. **`view_image` is a decompression bomb**: `image.Decode` without `DecodeConfig` (02-3).
6. **`rename` over an existing file silently clobbers it; `createFolder` over an existing folder answers 200** — the "409 on conflict"
   from BACKEND-GAP does not exist on the server (05-2).
7. **MySQL**: migration 00039 (`CREATE INDEX IF NOT EXISTS`) will not come up on MySQL 8; `INSERT OR IGNORE` / `LIMIT -1` in the shared Store —
   the assistant does not work on MySQL at all (01-1, 01-2, 04-3).
8. **Silence on errors in the UI**: no `errorHandler`/`unhandledrejection`; 12 places without a catch (share-link, Access, Versions, Tags,
   Destination, Home, Search, undo, capabilities…); `TagsModal` clobbers a file's tags when `listTags` fails (06-3).
9. **The demo stand runs `vite dev`** → dev hooks (`?caps=`, `?demo=`, the `search` monkeypatch) are live against a real backend (M3-1).

Product defects (Wave 1): the search scope `paths`/`tags`/`shared` never reaches the server (05-1); versions — the freshest snapshot is labeled
"Current" and cannot be restored (05-3); Recent sorts by modification date (05-4); an `openPath` race shows somebody else's folder under `/starred`
(06-1); five settings are saved and never read (06-2); `trash/empty` starves on a shared instance (03-3); `app/` has no path to production and not a single
CI step (08-1, 08-2); e2e runs only against the mock (08-3).

### 3.2 Backend: assistant tools, turn, plans (report 02)

## 4. What was done well (confirmed by the verifiers)

- **The model "a plan is a DB row, the server executes it without the model"**: an empty approve body, items resolved to node id + fingerprint at creation time, ownership through the session (IDOR by `planID` is impossible), `move` checks name availability with the driver, `restore` always takes a snapshot. `docs/ASSISTANT.md` is a strong threat-model document, almost entirely confirmed by the code. The two deviations (02-1, 02-2) are execution, not design.
- **Secrets**: the key is write-only (secretbox, `has_key`), "the address changed — enter the key again" closes the key-exfiltration vector and is covered by a test; the generic `/api/admin/settings` hides `assistant.*` on both read and write; the admin page does not echo the key.
- **Conversation privacy by construction**: the admin handler physically never calls `ListAssistantMessages`; the title is computed from the question alone, without scope or context (`assistant_turn.go:424`), and `cleanTitle` discards paths; checked through the real router.
- **SSE on both ends**: `ResponseController.Flush`, `defer release()` drops the lock even on a panic, a partial answer is saved on `WithoutCancel`; the client parser stitches partial frames, `reader.cancel()` is in `finally`, and stop really does cancel the provider.
- **The XSS surface is closed by construction**: not a single `v-html`/`innerHTML` in `app/src`; Markdown → tokens → elements; links only `http(s)` with `noopener`; `«»`-snippets via `<mark>`, not via HTML. Dev hooks do not make it into the prod bundle (proven by building it).
- **`NodeFacets.Where`** with a callback `bind`: one builder for sqlite/postgres, column names only from code, and the argument order generated together with the SQL — no injection, and drift between dialects is ruled out. The zone fix for `expires_at` was traced to its cause and covered by a non-UTC test.
- **The assistant's wire contract** matches field for field: `meta/text/tool/card/hits/report/title/error/done`, `cardEvent` ↔ `fromCard`, the approve response, `context` in camelCase. `context.ts` leaks no more than declared; the server does not persist the context.
- **The test style** of `versions_acl_test.go` (from the stranger's side, checking the bytes on disk after a 403) and `assistant_privacy_test.go` — this is exactly what should be replicated.
- **App**: the `loadSeq` guard in `load/read`, `operationsStore`/`queued` with a delayed reveal, validation of persisted state against an allowed set, above-average a11y (grid/listbox/`aria-activedescendant`/`aria-sort`, the headlessui focus trap), i18n parity of 549×3 with not a single hard-coded string in the templates, every global listener removed, and the Tailwind opacity-on-tokens trap never once hit.
- **e2e**: selectors by role and accessible name, assertions on the state after an action (Undo, Ctrl+Z "only one step"), `page.clock` for relative dates, one `waitForTimeout` across 1861 lines, and a config that explains every number with measurements.
- **Repository hygiene** is in order: `dist`/`shots`/`test-results` ignored, only two new packages in the lockfile, `.env.example` without secrets, and `docker-compose.app.yml` honestly listing what is not production-shape.

## 7. Assessment of the refactor as a whole

**The architecture is sound.** The Repository interface (58 methods, two implementations) held — no screen knows about HTTP. `name://path` as `Node.id` is right and cheap for a file manager with URL addressing (`getPath` with no requests, undo by address). Plan-based writes in the assistant are the best thing in the range. The capability snapshot is the right idea, but half the flags are currently client constants (`repository.ts:650-660`), because `/capabilities` answers for drivers, not for features.

**Three decisions that will be the most expensive to change later:**

1. **One sqlite `Store` for three dialects with no shared test run** (T1). Every new feature means two hand-written SQL statements and one check; the defects only surface in production on PG/MySQL. Either drop MySQL from the supported set now, or stand up the matrix now.
2. **The error contract in the data layer** (T3, M3-8): string messages as codes, `HttpError` beyond the layer boundary, `operations.run` that never throws, any 409 = "duplicate". Every new screen copies the pattern; moving to typed errors later = all 58 methods plus every catch.
3. **Mock-first e2e** (T2, T8): ~100 scenarios built on mock-dataset constants and on mock semantics that in three places are the opposite of the server's. Already today a green e2e run says nothing about production code.

The hidden cost of `name://path`, accepted by the product but already grown into two DB tables: `assistant_read_grants` and `notifications.node_path` are keyed by the path string and break on rename; `nodeId()` throws for a node not listed in the current tab (a deep link "star this file" is impossible). Recording this as a risk.
