## 1. Сводка: что чинить в первую очередь

Безопасность и потеря данных (Wave 0):

1. **ZIP-выгрузка отдаёт служебные каталоги** `.filex-trash`, `.versions`, `.thumbs` любому аккаунту, включая роль viewer —
   `GET /api/files/download/zip?path=main://` = все удалённые файлы всех пользователей и вся история версий (03-1).
2. **Activity-лента отдаёт share-токен** (в т.ч. drop-токен анонимной загрузки) любому ≥viewer файла (03-2).
3. **План ассистента может выполниться дважды**: `runPlan` идёт до захвата `pending`; два одобрения = две публичные ссылки /
   restore поверх restore; обрыв клиента оставляет полусделанный план `pending` (02-1). Клиент не защищает от двойного клика (07-1).
4. **Инструменты `list_trash` / `plan_empty_trash` видят корзину всей инсталляции** без ACL (02-2), вопреки `docs/ASSISTANT.md:75`.
5. **`view_image` — decompression bomb**: `image.Decode` без `DecodeConfig` (02-3).
6. **`rename` поверх существующего файла молча его затирает; `createFolder` поверх существующей папки отвечает 200** — «409 on conflict»
   из BACKEND-GAP не существует на сервере (05-2).
7. **MySQL**: миграция 00039 (`CREATE INDEX IF NOT EXISTS`) не поднимется на MySQL 8; `INSERT OR IGNORE` / `LIMIT -1` в общем Store —
   ассистент на MySQL не работает вовсе (01-1, 01-2, 04-3).
8. **Тишина при ошибках в UI**: нет `errorHandler`/`unhandledrejection`; 12 мест без catch (share-link, Access, Versions, Tags,
   Destination, Home, Search, undo, capabilities…); `TagsModal` при упавшем `listTags` затирает теги файла (06-3).
9. **Demo-стенд запускает `vite dev`** → dev-хуки (`?caps=`, `?demo=`, монкипатч `search`) живы против реального бэкенда (M3-1).

Продуктовые дефекты (Wave 1): search scope `paths`/`tags`/`shared` не доезжает до сервера (05-1); версии — свежайший снимок подписан
«Current» и не восстанавливается (05-3); Recent сортируется по дате изменения (05-4); гонка `openPath` показывает чужую папку под `/starred`

## 4. Что сделано хорошо (подтверждено верификаторами)

- **Модель «план — строка в БД, сервер исполняет без модели»**: пустое тело approve, элементы резолвятся в node id + fingerprint при создании, владение через сессию (IDOR по `planID` невозможен), `move` проверяет занятость имени у драйвера, `restore` всегда со снимком. `docs/ASSISTANT.md` — сильный threat-model документ, почти весь подтверждён кодом. Два отклонения (02-1, 02-2) — исполнение, не замысел.
- **Секреты**: ключ write-only (secretbox, `has_key`), «сменил адрес — введи ключ заново» закрывает вектор увода ключа и покрыт тестом; generic `/api/admin/settings` прячет `assistant.*` на чтение и запись; admin-страница ключ не эхо-ит.
- **Приватность бесед по построению**: admin-хендлер физически не вызывает `ListAssistantMessages`; заголовок считается только из вопроса без scope/контекста (`assistant_turn.go:424`), `cleanTitle` отбрасывает пути; проверено через реальный роутер.
- **SSE на обоих концах**: `ResponseController.Flush`, `defer release()` снимает lock и при панике, частичный ответ сохраняется на `WithoutCancel`; клиентский парсер склеивает частичные фреймы, `reader.cancel()` в `finally`, stop реально отменяет провайдера.
- **XSS-поверхность закрыта по построению**: ни одного `v-html`/`innerHTML` в `app/src`; Markdown → токены → элементы; ссылки только `http(s)` с `noopener`; `«»`-сниппеты через `<mark>`, не через HTML. Dev-хуки в prod-бандл не попадают (доказано сборкой).
- **`NodeFacets.Where`** с callback-`bind`: один билдер для sqlite/postgres, имена колонок только из кода, порядок аргументов генерируется вместе с SQL — инъекции нет, дрейф между диалектами исключён. Фикс зон для `expires_at` разобран до причины и покрыт non-UTC тестом.
- **Wire-контракт ассистента** совпадает поле в поле: `meta/text/tool/card/hits/report/title/error/done`, `cardEvent` ↔ `fromCard`, approve-ответ, `context` camelCase. `context.ts` не утекает больше, чем заявлено; сервер контекст не сохраняет.
- **Стиль тестов** `versions_acl_test.go` (со стороны чужого, проверка байт на диске после 403) и `assistant_privacy_test.go` — именно это надо тиражировать.
- **App**: `loadSeq`-guard в `load/read`, `operationsStore`/`queued` с отложенным показом, валидация persisted-состояния против allowed-set, a11y выше среднего (grid/listbox/`aria-activedescendant`/`aria-sort`, headlessui focus trap), i18n-паритет 549×3 без единой жёсткой строки в шаблонах, все глобальные слушатели снимаются, Tailwind-ловушка с opacity на токенах не задета ни разу.

## 7. Оценка рефакторинга в целом

**Архитектура здрава.** Repository-интерфейс (58 методов, две реализации) удержан — ни один экран не знает про HTTP. `name://path` как `Node.id` для файлового менеджера с URL-адресацией правильно и дёшево (`getPath` без запросов, undo по адресу). Plan-based writes у ассистента — лучшее в диапазоне. Capability snapshot — идея верная, но половина флагов сейчас константы клиента (`repository.ts:650-660`), потому что `/capabilities` отвечает за драйверы, а не за фичи.

**Три решения, которые дороже всего менять потом:**

1. **Один sqlite-`Store` на три диалекта без общего тестового прогона** (T1). Каждая новая функция — два ручных SQL и одна проверка; дефекты вылезают только в проде на PG/MySQL. Либо убрать MySQL из поддерживаемых сейчас, либо поднять матрицу сейчас.
2. **Контракт ошибок в data-слое** (T3, M3-8): строковые сообщения как коды, `HttpError` за границей слоя, `operations.run` никогда не бросает, любой 409 = «дубликат». Каждый новый экран копирует паттерн; переход на типизированные ошибки позже = все 58 методов + каждый catch.
3. **Mock-first e2e** (T2, T8): ~100 сценариев на константах мок-датасета и на семантике мока, которая в трёх местах противоположна серверу. Уже сейчас зелёный e2e ничего не говорит о продовом коде.

Скрытая цена `name://path`, принятая продуктом, но уже проросшая в две таблицы БД: `assistant_read_grants` и `notifications.node_path` ключуются строкой пути и рвутся при rename; `nodeId()` бросает для узла, не перечисленного в этой вкладке (deep-link «звезда на файл» невозможен). Фиксирую как риск.

## 9. Открытые вопросы к владельцу продукта

1. Статус MySQL: поддерживать ассистент и новые фичи на нём, или официально «sqlite + PostgreSQL»? От ответа зависит W0-6 (M) против одной строки в docs.
2. Ассистент видит корзину всей инсталляции (как admin) или «корзину человека», как страница Trash? Docs обещают второе.
3. «Только dev-сервер, без embed в Go» для `app/` — осознанное решение на этот этап? Если да, зафиксировать в BACKEND-GAP и убрать ложный комментарий из `vite.config.ts`.
4. Планируется ли коммитить подмножество `drive-demo-assets` в репозиторий (fixture для e2e) или чинить через fail-fast?
5. Нет кнопки Stop в панели ассистента: прервать ход можно только закрытием панели/Escape. Осознанно?
6. После approve плана клиент отправляет от имени пользователя фразу «I approved the plan…» как обычный ход (тратит лимит, теряется при `!canSend`). Задумано так, или исход должен уходить серверно?
7. Rate-limit `turns_per_minute` и lock «один ход на аккаунт» живут в памяти процесса — при нескольких репликах не действуют. Ожидаемо?
8. `defaultUploadFolder` хранит node id (= путь), который меняется при rename — для настройки приемлемо?
9. Activity keyed by path: после delete+recreate новый файл наследует историю старого (включая чужие `share.created`). Осознанно?
